## Monaco 问题定位与修复

上一批桌面回归中的 `Trying to add a disposable to a DisposableStore that has already been disposed of` 来自 Monaco 0.56.0 的 SuggestModel。

`_waitForInlineCompletionsAndTrigger` 调用 `store.add(autorun(...))`，但 autorun 在返回监听器之前先同步执行回调。补全已结束或模型已切换时，回调会释放 store，随后 add 把监听器登记到已释放的容器，打印泄漏日志。故障不只限于用户关闭编辑器，也可在首次读取补全状态时触发。

- 安装时补丁先获取 autorun 返回的监听器；容器仍有效才登记，否则立即释放监听器。保留自动补全功能，不屏蔽错误日志。
- 补丁可重复运行；上游目标代码改变时安装明确失败，要求重新核对，而不是悄悄跳过。仅修改构建依赖，不在应用运行时改文件。
- RemoteEditorView 释放时清空 editorRef、停止延迟布局观察，并以文档 ID 隔离编辑器实例。
- 单元测试直接执行目标方法，覆盖首次同步完成及等待中模型释放。桌面回归捕获此类日志并将其作为失败条件，额外等待迟到的补全/布局回调。

## 工作区恢复

本批恢复范围是运行状态镜像、Agent 查看工作区和关闭/重开期间的异步结果，不新增跨进程重启的终端内容或未保存文件持久化。

- 新增 watchSnapshot，人工输入待办和审批问题统一采用先订阅、再读取快照、合并期间变化的顺序。新请求覆盖旧快照，已完成的待办不会被旧快照复活；退订后忽略快照与事件回调。
- 恢复失败保留已知状态并提供显式重试；连接登记快照同样接入该错误入口，继续沿用其 revision 排序规则。
- 工作区连接回复受关闭版本约束，关闭后迟到的成功或失败不会重新打开工作区。查看工作区升级期间同样校验。
- 导航按最近一次进入意图处理；用户转去设置或另一个主机后，先前连接回复不能抢回焦点。并发连接仍只创建一个主机工作区。
- 用户工作区与 Agent 查看工作区共用初始化入口。Agent 查看页直接读取已有连接镜像，不为恢复查看页创建额外用户 SSH 连接。
- 终端创建失败会释放已分配的远端 Shell，并允许用户重试；重试等待创建结束，防止重复点击。终端模块加载失败后允许再次加载。
- 远程文件关闭后，迟到的大文件读取结果不再生成旧工作区提示；旧保存完成不能批准关闭后来打开的新文档或工作区。

## 错误呈现

- 工作区恢复、终端创建、凭据保存和偏好加载失败统一进入 WorkspaceIssues，按操作范围保留提示，提供适用的重试和关闭入口。重试期间禁用按钮，成功后清除对应问题。
- 登录凭据保存失败不再形成未处理的 Promise 拒绝。重试仅保存凭据，不重新登录；关闭工作区或提交新登录信息后，旧重试及旧错误回调失效。
- errorMessage 统一读取 Error 和序列化错误的 message，并去掉 Electron invoke 包装，保留实际失败原因。
- 远程文档继续在编辑器内显示读写错误；有错误时不再同时显示“已保存”。保存失败保留未保存内容和关闭保护。
- 新提示使用现有 AT 按钮、原生 disabled、字号 token，并提供中英文文案。
