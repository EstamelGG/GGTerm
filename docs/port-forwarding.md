# 端口转发

右侧活动栏的「端口转发」管理所有主机的 TCP 转发。左侧主机右键菜单与主机表格的更多菜单都有「新增端口转发」和「查看端口转发」入口。

## 规则

- 本地转发：本机监听，经 SSH 主机连接目标。目标域名由 SSH 服务端解析。
- 远程转发：SSH 主机监听，经 SSH 连接本机目标。目标域名由本机解析。
- 默认监听 `127.0.0.1`，同时支持 IPv6 地址。远程监听范围受服务端转发策略与 `GatewayPorts` 限制。
- 「保存」只保存配置；「保存并启动」建立监听。监听成功和目标可达分别显示，目标测试只建立并关闭 TCP 连接，不验证应用协议。
- 同一监听端口冲突会报错，不自动改端口。运行中的规则必须先停止才能编辑。
- 「复制规则」保存一份停止状态的副本并打开编辑器，启动策略回到手动。

## 生命周期

保存的规则在 app 启动后保持停止。「连接此主机时启动」只在用户建立该主机连接时触发，不主动在 app 启动时拨号。用户手动停止后，当前 SSH 连接的自动重连不会将其重新启动。

关闭终端标签、切换页面、折叠侧栏不停止转发。SSH 意外断线会关闭旧 TCP 连接，在链路恢复后重新建立监听；旧连接无法恢复。主动关闭 SSH 停止挂在该连接上的转发。用户 SSH 和各 Agent 对话的 SSH 相互隔离。

停止转发关闭监听与已有 TCP 连接；重启等待旧监听释放后重新建立。退出 app 释放全部运行资源。删除主机时停止转发并保留规则；卡片以浅红背景和「主机已删除」标题提示显示，可编辑并重新关联其他主机。

Agent 创建的规则属于当前对话，不持久化；删除对话时清理。用户可以停止任何规则，也可以「保存为我的规则并停止」，随后手动启动到用户 SSH 连接，避免持续依赖原 Agent 对话。

使用手动认证的主机应先完成主机连接与凭据输入，再启动转发。首版不包含 SOCKS5、UDP、Unix socket 转发和浏览器协议识别。

## Agent tools

| 工具                     | 行为                                                           |
| ------------------------ | -------------------------------------------------------------- |
| `list_port_forwards`     | 查看所有规则与状态，返回 `owner` 和 `mine`，可按 `hostId` 筛选 |
| `configure_port_forward` | 创建或完整修改当前对话的临时规则，不启动                       |
| `control_port_forward`   | 启动、停止、重启、删除当前对话的规则                           |
| `probe_port_forward`     | 测试当前对话规则的目标 TCP 可达性                              |

修改与控制接入现有配置审批；规则 ID 的归属在主进程验证，不依赖模型自律。每条规则的启停按顺序执行，不同对话争用监听端口由统一管理器和操作系统检查。

## 实现与验证

`PortForwardManager` 统一持有监听、SSH 通道和连接统计；规则配置单独保存至 `port-forwards.json`。UI 经 preload IPC 读取并订阅快照；Agent tools 调用同一服务。用户转发复用用户 `HostLink`，临时转发复用该对话的独立 `HostLink`。

`tests/port-forward.test.ts` 验证真实 TCP 流量、半关闭、端口冲突、监听清理、重连、归属隔离，以及真实 ssh2 服务端握手和转发通道。

`tests/electron-port-forward-smoke.cjs` 使用隔离的 app 数据验证真实 renderer、preload、IPC、保存规则、主机删除后保留卡片和头部分割线对齐。
