# AI 恢复与上下文压缩

## 自动恢复

- 网络断开、连接重置、超时、HTTP 408/429/5xx 会自动重试失败的模型请求。
- 默认最多重试 5 次，等待 2、4、8、16、30 秒；有 `Retry-After` 时等待较长的间隔（最多 60 秒）。摘要请求也有独立的恢复预算。
- 输入区显示重试次数、倒计时和恢复状态。恢复期间会话保持忙碌，点击停止会取消当前请求及等待，不会在后台再次重试。
- API Key、权限、额度和请求配置等永久错误直接显示错误，不会反复请求。
- 已完成的工具步骤及审批结果保留。失败采样产生的工具调用只有收到完整结束标记后才可执行，因此不会因断线重放已完成操作。恢复成功后移除失败采样的残缺文本，保留成功回复与工具结果。
- 恢复范围是当前进程内正在运行的回合；重启应用不会自动续跑旧任务。

## 自动压缩

- 每轮开始及每个工具步骤之前检查上下文；默认输入预算为配置窗口的 70%，包含系统指令及工具定义，为输出和估算误差留余量。
- 使用 UTF-8 字节估算，并按 provider 返回的实际输入量校准同一会话、同一模型后续请求的预算。
- 优先摘要较早的完整用户回合。单轮长任务也可在已完成的工具步骤之间压缩，最新用户请求保持原文；调用及结果不得拆散。
- 压缩后的近期上下文目标为可用消息预算的 55%，给摘要和后续工具结果留出空间。
- 如果保留最近步骤仍超限，再缩减过大的工具输出，保留首尾及明确的省略说明；完整结果仍在聊天历史中，模型需重新查询被省略的信息。
- provider 报上下文超限时，即使本地估算低于配置阈值，也强制减少上下文后重试；每个采样请求最多进行两次这样的修复。
- 摘要模型请求分块进行，支持网络恢复；摘要为空、过长或被截断时，以更明确的长度约束再生成一次，不直接截断摘要。只在摘要有效、最终输入确实满足预算后替换模型输入。失败或取消不会覆盖完整历史或有效摘要。
- 原始请求本身超过窗口、工具定义占满窗口、或最新工具结果无法安全缩减时仍会明确报错；不会截断用户约束或拆散工具配对。
