# 重构第四批：资源标识、失效规则与 Windows 终端清理

日期：2026-11-03。恢复成果先保存为本地提交 `2f77976`；该检查点包含前三批和第四批的部分基础代码。本记录覆盖完整第四批。

## 保留的功能与统一边界

- 保留多终端、用户/Agent 连接隔离、SFTP 浏览和传输、远程编辑、列表/会话性能面板与 GPU 指标。
- Shell、SFTP、性能及 GPU 采样统一使用 ResourceIdentity：hostId、kind、resourceId、generation，以及所属 SSH connectionId/connectionGeneration。配置主机 ID 不再充当运行资源的唯一身份。
- ResourceLifetime 统一资源版本与 AbortSignal；资源重启只使自身旧任务失效，SSH 传输失效则使该传输的所有资源租约失效。已失效的传输不能因为之后才创建资源而重新有效。
- 身份附加到 Shell 状态/输出、SFTP 状态及性能样本。保留兼容字段和现有 IPC 通道，不将高频输出混入连接状态事件，也不修改存储格式。

## 生命周期修复

- Shell 开通道超时后关闭迟到通道；重连或主动关闭作废旧输出、延迟启动命令和排队输入。写队列绑定原通道，旧输入不会转入新终端；失效时结束等待，避免遗留写定时器。
- SFTP 请求同时绑定资源版本和具体通道；即使在 await 间隙发生关闭，也不继续对旧通道发请求。失效中断等待中的目录请求、文件读取和原子保存，目录删除的 exec 也支持中止。
- SFTP 失效同时取消传输任务和目录测量；旧测量完成消息不再覆盖新面板。远程编辑保留原有临时文件加原子重命名策略，断连后不跨连接继续保存。
- 性能采样在获取连接前、执行脚本后均检查有效性；暂停、关闭、连接切换后的迟到结果不会发布。旧采样的 finally 不得解除新采样的执行锁；切换传输时重置网速、每核和磁盘速率基准。
- GPU 面板关闭后重新打开同一主机，旧结果仍被丢弃；先打开面板、连接稍后上线时也能开始采样。

## Windows 原生终端清理

- 根因：node-pty 1.1.0 的 ConPTY 清理先异步启动进程枚举助手，随后立即关闭原生控制台；助手稍后 AttachConsole 时控制台已不存在。
- 安装脚本先枚举控制台进程，再终止进程树和释放原生句柄；重复 kill 幂等。助手退出、启动错误和超时均会结束等待，错误仍明确记录。
- 自然退出仍可能发生在枚举期间：仅当 AttachConsole 失败且系统确认 shell PID 已不存在时，按空列表处理；其他错误不静默吞掉。
- 补丁在 postinstall 应用，重复执行安全，目标源码不匹配时明确失败，避免升级依赖后悄悄失效。运行中的已安装应用不修改自身文件。
- 应用退出会等待已由窗口销毁触发的 PTY 清理，最多等待 6 秒，超时记录错误，避免主进程先退出导致清理中断。此上限不是对系统异常情况下清理成功的保证。
- 新增 `npm run test:pty-cleanup`：快速和重复关闭、自然退出、子进程树释放、独立终端存活；即使主测试通过，原生辅助进程的清理报错仍使回归失败。已接入 Windows CI 的 test 任务。
